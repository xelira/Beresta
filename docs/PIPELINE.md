# Как устроен компилятор

## Конвейер

```
файл.бер
   │  lexer.cpp       UTF-8 → vector<Token>
   ▼
токены
   │  parser.cpp      рекурсивный спуск → AST
   ▼
AST (unique_ptr, узлы ast.hpp)
   │  sema.cpp        таблицы символов, типы, привязка имён
   ▼
размеченный AST
   │  codegen.cpp     x86-64, AT&T, GNU as
   ▼
файл.s
   │  as --64
   ▼
файл.o
   │  cc
   ▼
ELF-исполняемый файл
```

Фронтенд ничего не знает о машине, бэкенд ничего не знает о синтаксисе. Общая
граница — `ast.hpp` плюс `symbol.hpp`: после семантики каждый `Ident`, вызов и
объявление уже связаны с `Symbol` и типом, кодогенератору не нужно разрешать
имена заново.

## Модули

`modules.cpp` до разбора склеивает файлы:

1. Читает файл построчно.
2. Строки `привлечь "путь";` заменяет пустой строкой и рекурсивно подключает
   файл (путь относительно текущего).
3. Повторные подключения игнорирует, циклы запрещает.
4. Запоминает для каждого файла диапазон строк в общем исходнике.
5. При ошибке `remap()` переводит строку общего исходника в настоящий файл и
   локальную строку, поэтому диагностика указывает на модуль.

## Семантика

- Два прохода по объявлениям: сначала регистрируются все функции (рекурсия и
  вызовы вперёд), затем проверяются константы, затем тела.
- Области видимости — связный список `Scope` с `unordered_map` имён.
- Каждому имени выдаётся уникальное C-имя (`b_7`, `f_3`, `c_2`), чтобы
  кириллица не попадала в ассемблерные метки.
- `Symbol` живёт в `Program::symbols`, дерево держит сырые указатели.

## Соглашение о вызовах

x86-64 System V AMD64:

- Целые/указатели/флаги: `rdi, rsi, rdx, rcx, r8, r9`.
- Дробные: `xmm0..xmm7`.
- Возврат: `rax` или `xmm0`.
- `rbp`, `rbx`, `r12–r15` — callee-saved. Бэкенд трогает только `rbp`
  (сохраняет в прологе) и не использует остальные кале-сейв регистры.
- Перед `call` `rsp` выровнен по 16 байт. Компилятор ведёт `stack_depth_` и
  добавляет выравнивающие 8 байт при нечётной глубине.

## Кадр функции

```
        ┌──────────────┐
rbp+16  │ аргументы на │
        │ стеке (нет)  │
rbp+8   │ адрес возврата │
rbp     │ старый rbp   │
        ├──────────────┤
-8      │ слот 0       │
-16     │ слот 1       │
 ...    │ ...          │
        └──────────────┘
```

- Каждый слот — 8 байт независимо от типа: `число`, `флаг` и указатель лежат
  как есть, `дробь` — через `movsd`.
- Массив занимает `N` подряд идущих слотов. Элемент `i` лежит по адресу
  `-8 * (slot + N - i)`, поэтому индекс умножается на 8 без вычитаний.
- Индексация проверяет `0 <= i < N` и паникует при выходе за границы.
- Все переменные живут в слотах, регистры — только для вычислений.
- Промежуточные значения выражений — `push`/`pop`, поэтому кодогенерация простая
  и предсказуемая.
- Размер кадра выравнивается до 16.

## Выражения

- Целые и указатели вычисляются в `rax`, дроби — в `xmm0`.
- Левый операнд бинарной операции кладётся на стек, правый считается после него,
  затем левый поднимается в `rcx`/`xmm1`. Это даёт корректный порядок вычислений
  и не требует анализа глубины дерева.
- Для смешанной арифметики `число` превращается в `дробь` через `cvtsi2sdq`.
- Сравнения строк — `strcmp`, конкатенация — `b_str_concat`.
- `и`/`или` компилируются в короткое замыкание с метками.
- Константные выражения из литералов сворачиваются в кодогенераторе: `2 + 3 * 4`
  превращается в `mov $14, %rax`.

## Циклы

- `доколе` — условие, тело, безусловный переход назад.
- `повтор` — начало, границы и шаг сохраняются в слоты (по одному разу), затем
  сравнение с учётом знака шага и инкремент в конце. `продолжить` прыгает на
  инкремент, `прервать` — на выход.

## Рантайм

Рантайм написан на ассемблере прямо в `codegen.cpp` и вставляется в каждый
файл. Он не компилируется из C.

| Функция | Назначение |
|---|---|
| `b_panic` | сообщение в stderr, `fflush(stdout)`, выход 1 |
| `b_div`, `b_mod` | проверка деления на ноль |
| `b_str_concat` | `strlen` + `malloc` + `strcpy` + `strcat` |
| `b_str_len` | длина UTF-8 в символах |
| `b_str_from_int` | `snprintf("%ld")` |
| `b_str_from_float` | `snprintf("%.15g")` |
| `b_str_from_bool` | `правда` / `кривда` |
| `b_str_to_int` | `strtoll` |
| `b_read_line` | `read(2)` побайтно в растущий буфер |
| `b_read_file` | `fopen`/`fseek`/`ftell`/`fread`, файл целиком |
| `b_write_file` | `fopen`/`fputs`/`fclose`, запись файла |
| `b_gc_alloc` | выделение блока с заголовком и контролем порога |
| `b_gc_realloc` | рост буфера без потери данных |
| `b_gc_collect` | сканирование стека, пометка, зачистка |
| `b_gc_mark` | пометить блок, если указатель попал внутрь |

libc используется как ABI-слой: `malloc`, `read`, `printf` и т. п. Компилятор
при этом сам решает, какие инструкции и когда вызвать.

## Ассемблерный вывод

- Синтаксис AT&T, директивы GNU as.
- Секции: `.text` (код и рантайм), `.data` (константы), `.rodata` (строки,
  форматы, сообщения).
- Метки генерируются уникально (`.Lif_end_12`), имена функций — `f_N`.
- `.section .note.GNU-stack,"",@progbits` — стек неисполняемый.
- Код собирается без PIE-специфичных ухищрений: адреса — `rip`-relative,
  внешние вызовы — через PLT.

## Отладка

```sh
berestac asm пример.бер -o пример.s   # посмотреть, что вышло
berestac ast пример.бер               # посмотреть дерево
berestac tokens пример.бер            # посмотреть токены
berestac check пример.бер             # только проверки
```

## Куда добавлять новое

1. Лексема — `token.hpp`/`lexer.cpp`.
2. Синтаксис — узел в `ast.hpp`, разбор в `parser.cpp`.
3. Правила типов — `sema.cpp`.
4. Код — `codegen.cpp`; при необходимости — рантайм-функция в `RUNTIME`.
5. Документация — `docs/SPEC.md` и `docs/GRAMMAR.md`.
