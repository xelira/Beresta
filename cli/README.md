# Лаунчер `beresta`

Одна команда вместо флагов компилятора: файл или папка → сборка → запуск с
выводом.

```sh
beresta run пример.бер
beresta run моя_программа/
beresta build моя_программа -o моя_программа.bin
beresta check моя_программа
beresta new новая_программа
beresta doctor
```

## Как ищется точка входа

Если указана папка, лаунчер берёт:

1. `главная.бер`;
2. `main.бер`;
3. `береста.бер`;
4. единственный файл с блоком `береста`;
5. если файл один — его.

Остальные файлы подключаются сами через `привлечь`.

## Где берётся компилятор

По порядку:

1. вложенный `berestac` (сборка с тегом `bundle` — так собирается релизный
   `beresta-linux-amd64`; при первом запуске он распаковывается в кэш);
2. `BERESTAC` из окружения;
3. `berestac` рядом с лаунчером;
4. `berestac` в `PATH`.

Ассемблер и линкер (`as`, `cc`) — системные. Их ставит установщик.

## Windows

`beresta-windows-amd64.exe` — обычный консольный `.exe`.

- Если рядом (или в `PATH`) есть `berestac.exe`, лаунчер работает **нативно**:
  сборка и запуск без WSL, на настоящем Windows-компиляторе.
- Если нативного компилятора нет, лаунчер откатывается на WSL: пути переводятся
  через `wslpath`, вывод и код возврата пробрасываются.

Нативный режим ставит установщик: `beresta-install.exe` скачивает компилятор и
MinGW-w64.

## Вложенный компилятор

`make launcher-bundle` собирает `build/beresta-bundle`: внутри один файл,
в который через `go:embed` упакован `berestac`. Компилятор распаковывается в
`~/.cache/beresta/bin` и используется как обычно.

GCC внутрь не встраивается: полноценный тулчейн — это сотни мегабайт и
GPL-лицензия. `beresta` использует системный `as`/`cc`, а установщик умеет
ставить их сам.
